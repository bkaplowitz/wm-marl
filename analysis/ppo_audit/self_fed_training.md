# Isolated recurrent CTDE training experiment

Prepared on `codex/ma-jepa-self-fed-training` from corrected baseline
`2663ae57ab80482ad201f9c3bdaa9fe2c732dbe9`. This is an unpromoted experiment,
not evidence of improved control performance. No training job was launched by
this implementation task.

## Hypothesis and limits

The deployed joint simulator repeatedly consumes its own predicted embedding
through the local categorical posterior. The factual one-step objective trains
on factual local states. Existing direct multi-step JEPA predicts a distant
embedding with a separate head and does not train this recurrent path. The new
auxiliary exposes the existing one-step joint predictor and outcome heads to
states generated by their own preceding predictions, using recorded actions.

Root construction deliberately retains the world branch's saved-code prefix
burn-in. PPO rebuilds its behavior prefix from current raw observations instead.
Rebuilding the joint suffix snapshots in inference mode removes joint dropout
differences, but does **not** remove this local-prefix mismatch or mixed-age code
seams. This first experiment isolates recurrent exposure training while leaving
the existing world-root distribution fixed; it is not an exact match to PPO's
root distribution.

This is supervised world-model training on behavior replay. It does not treat
recorded actions as current-policy samples, add an off-policy actor objective,
or provide target information to the decentralized actor. Replay coverage and
action mismatch remain limitations. It cannot establish that more accurate
replay rollouts improve the policy's counterfactual actions. A paired frozen
simulator audit and fresh seeded control experiments are still required.

## Configuration

```yaml
agent:
  marl:
    ctde:
      self_fed:
        enabled: false
        horizons: [2, 4, 5]
        anchors: 8
        scale: 0.1
        consumer_kl_scale: 0.0
```

`enabled: false` and `enabled: true, scale: 0` both skip the complete hook,
additional loss keys, and random draws. Older configs without `self_fed` remain
accepted. The optional hook creates no new model parameters. The common scale
multiplies existing `ctde_{embedding,interface,reward,continuation,action_mask,alive}`
relative scales. Consumer KL has effective weight
`scale * consumer_kl_scale`; it is separately disabled by default. These are
provisional experiment values, not tuned recommendations.

This implementation targets the baseline hard CTDE mask/liveness path. It
does not support the separately calibrated local-mask/soft-liveness treatment.
Horizon values must be sorted, distinct, and between 2 and 15; optimized replay
must contain at least three states. At most `anchors` roots are sampled across
the complete world batch. When fewer eligible roots exist, padded root slots
are computed but contribute zero loss.

## Forward and target contract

1. Rebuild deterministic joint snapshots from the same stopped factual local
   states, recorded actions, and prefix joint carry used by the ordinary replay
   objective. This extra joint pass uses `training=False`. Existing one-step
   training snapshots include dropout and are intentionally not reused.
2. Sample roots with an observed valid two-transition path and a live root
   cohort. Read the local posterior/cache at state `t` and the joint cache before
   predicting `t+1`. Detach both caches and all factual targets.
3. At transition `h`, read recorded previous-action entry `prevact[t+h]` to
   produce the state arriving at `t+h`. Use the existing joint predictor with
   `training=False`, the existing local advance, and
   `complete_from_observation(..., sample=True)`.
4. Threshold predicted liveness at 0.5 and conjoin it with preceding liveness
   and the root roster. Threshold the predicted action mask at 0.5; use no-op
   when no action survives or the unit is predicted dead. Recorded actions
   remain the transition inputs even when this predicted support excludes
   them, because replacing them would invalidate the real targets.
5. Detach the complete generated state before the next transition. At selected
   endpoints train cosine to stopped EMA embeddings, smooth L1 to stopped
   online embeddings, and existing reward/continuation/mask/alive head losses.
   Reward targets are `reward[t+h]`, and continuation targets use
   `is_terminal[t+h]`, including the existing `contdisc` factor.

For each root and slot, endpoint validity ends at the first reset, roster
absence, previous-state `is_last`, or batch end. A terminal arrival itself is
valid. H2 roots near the end of an episode therefore remain usable even when
H4/H5 are masked. No target or gradient crosses a reset. Local embedding,
interface, action-mask, and alive losses retain the **root-live** cohort across
valid endpoints; an actual death after the root does not remove later
corrections when the simulator still predicts that unit alive.

Reward and continuation losses retain all present root slots, including slots
already dead at the root. Their scalar sum is placed on eligible learner rows
at that root so the learner's outer mask cannot remove dead-head gradients.
This placement preserves the sampled valid-head mean. Each configured horizon
has weight `1 / len(horizons)` and independently averages its valid sampled
heads; unavailable horizons contribute zero rather than redistributing their
weight. The horizon mixture and two-step root requirement introduce an
explicit sampling bias toward states with two observed future transitions.

In maintained SMAC, `agent_alive` remains true for the complete present roster;
physical death is represented by `controllable_alive`. Consequently the outer
learner mask already includes physically dead SMAC slots. The redistribution
is a robustness measure for other valid metadata profiles where `agent_alive`
also becomes false; it is not a loss omission observed in the maintained SMAC
baseline.

## Gradient contract

The auxiliary updates only the existing joint predictor and outcome heads.
Encoder, EMA encoder, local dynamics/posterior, decentralized actor, central
critic, slow critic, and teammate modules receive zero auxiliary gradient.
Recurrent state generation remains stochastic, but all state between steps is
stopped. This is last-transition supervision; it is not full backpropagation
through imagined trajectories.

If enabled separately, consumer KL differentiates through a frozen copy of the
local posterior parameters into the predicted embedding only. Both predicted
and factual online embeddings are evaluated with the **same stopped self-fed
deterministic state**. The teacher distribution is stopped, and KL uses the
actual categorical unimix probabilities. This measures compatibility at a
fixed consumer state rather than asking the embedding to compensate for the
difference between factual and imagined deterministic states.

The hard liveness gate is monotone, and gradients do not cross it or a previous
step. A falsely predicted death can therefore remain irreversible within a
rollout. Later raw-head supervision can correct the shared predictor on that
input, but cannot directly credit an earlier survival decision. Losses at
H2/H4/H5 also leave H3 without a direct auxiliary endpoint. These limitations
are deliberate for the first bounded exposure-training experiment.

## Diagnostics and cost

Loss keys are `ctde_self_fed_{embedding,interface,reward,continuation,action_mask,alive}`
and, only with nonzero KL scale, `ctde_self_fed_consumer_kl`. Metrics are under
`ctde/self_fed_train/` and `ctde/self_fed_train_h{h}/`. They record eligible and
sampled roots, per-horizon present/root-live counts, losses, embedding cosine,
shared deployed reward error, continuation error, hard liveness error, action
mask error, and the fraction of recorded actions excluded by predicted support.
`alive_brier` here evaluates hard deployed liveness, not the raw alive-head
probability; compare like metrics when interpreting reports.

The hook adds one inference-mode factual joint pass over `B * (L-1)` team
transitions and `K * max(horizons)` generated team transitions. Each generated
transition also executes frozen local advance/posterior and outcome heads.
The optional KL adds two posterior evaluations per generated transition.
Counts are logged as `joint_snapshot_transitions` and `rollout_transitions`;
these are arithmetic workload counts, not a throughput measurement. GPU
throughput and memory overhead have not been measured. The original one-step
objective, its dropout behavior, and all original optimizer ownership remain
unchanged.

## Prepared production-size gate

`scripts/gate_self_fed_production.py` is a separate disposable resource gate,
not a learning experiment. It preserves the saved 2s3z architecture, optimized
batch size/length, prefix lengths, replay modes, PPO settings and GPU platform;
it changes only the optional auxiliary and single-device/output/precompile
settings. It copies the frozen checkpoint and replay files before constructing
the canonical runtime. Three updates are the default (hard limit five), with
no actor actions, environment collection, or checkpoint saves. `--disabled-control`
uses the same source/config with the auxiliary disabled for a matched cost
comparison. A fresh output directory is mandatory for every invocation.

The gate saves complete scalar learner metrics, H2/H4/H5 valid counts, all-state
finiteness, optimizer/update/action counters, source/input hashes and runtime
versions. Update0 includes compilation; subsequent update timing includes a
synchronization fence. JAX memory counters and a 250ms `nvidia-smi` process-memory
sampler capture peak allocation. `memory.json` is refreshed independently so
an OOM process abort can still leave a memory record. Serialized replay codes
remain an imperfect copy of final in-memory replay, as noted in the burn-in
review; this gate assesses executability/resource cost, not control quality.

Preparation tests pass, but no production GPU result exists yet. Execute only
after the parent has assigned an idle GPU following final-checkpoint/evaluation
preservation. The frozen inputs are:

```text

--checkpoint /workspace/majepa_diagnostics_data_20260905/ckpt/20260905T074720F566169

```

Set `CUDA_VISIBLE_DEVICES` to the assigned device, use the staged optional
source and maintained external runtime on `PYTHONPATH`, and pass a new
`--output` directory. `--validate-only` copies/verifies inputs and resolves the
config without initializing a GPU, updating parameters, or creating an env.
